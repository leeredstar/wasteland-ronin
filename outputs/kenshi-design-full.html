荒原浪人 · 完整设计方案

WASTELAND RONIN — 仿 Kenshi 的网页 2D 沙盒生存游戏 · 全量设计文档

本文档在现有雏形（index.html / js/game.js / css/style.css + 两个 Node 无头测试）基础上，给出一套可直接落地的完整设计：从目标定位、技术选型、目录结构、数据模型，到每个系统的细节、内容规划、开发里程碑、测试与风险。逻辑与表现分离、数据驱动，沿用你已有的无头测试体系。

一、项目定位与范围

类型：俯视 2D、开放世界沙盒、小队策略生存 RPG。核心体验关键词：没有主线任务、组建小队、在荒原求生/变强/厮杀、断肢残躯也能续命。

维度定位说明
平台纯前端浏览器无需后端，localStorage 存档；可一键打包为桌面/离线页
视角俯视 2DCanvas 渲染，世界坐标 → 屏幕坐标经相机变换
节奏实时 + 暂停可选默认实时 tick，战斗/移动连续；睡眠切到天亮做时间跳跃
MVP 边界先保核心移动 / 战斗 / 生存 / 招募 跑通即为 MVP；建造、经济、剧情为增量
非目标不做不做 3D、不做联网对战、不做复杂剧情分支、不做美术资源管线（先用色块/SVG）

二、技术选型

渲染

Canvas 2D

  • 实体/地形用色块+图标，不依赖外部美术
  • 视口裁剪 + 离屏缓存静态层
  • 暂不引入 WebGL/Three（过早优化）
语言

原生 JS (ESM)

  • ES Modules，按模块拆分，无重型框架
  • 可选轻量打包（esbuild）做单文件发布
架构

逻辑/表现分离

  • 逻辑层不引用 DOM，可被无头运行
  • 表现层只读取状态后渲染
测试

Node 无头 + Vitest

  • 沿用你已有的 sandbox 桩
  • 核心系统用单元测试 + 冒烟回归

四、数据模型（完整）

Kenshi 的灵魂是部位独立受伤：角色不是单血条，而是六个部位各有 HP，部位状态直接改变行为能力（手臂伤→挥击弱且慢、腿伤→移速降、胸归零→倒地流血、头归零→昏迷）。

关键字段（伪代码）

Unit = {
  id, faction: 'player'|'bandit'|'hungry'|'beast',
  x, y, speed,
  state: 'idle'|'moving'|'attacking'|'down'|'dead',
  body: { head:{hp,max}, chest:{hp,max}, armL:{hp,max}, armR:{hp,max}, legL:{hp,max}, legR:{hp,max} },
  skills: { str, toughness, dodge, melee },
  eq: { weapon, armor },
  inventory: [{type, qty}],
  hunger, bleeding, downTimer, lastAttacker
}

五、核心系统详细设计

5.1 战斗系统 Combat

  • 命中判定：攻击方命中率 = f(melee, 闪避差)；命中后随机选部位（头/胸/双臂/双腿加权）。
  • 伤害结算：基础伤害 × 部位系数 × 韧性减伤；胸归零→倒地+流血，头归零→直接昏迷。
  • 流血：倒地后每秒掉血，到 −60% 死亡；脱离战斗缓慢自愈；绷带（C）即时处理。
  • 救援/俘虏：R 救助倒地友军；X 俘虏倒地敌人→搬运战利品，再按 X 释放。
  • 后果：手臂伤→攻击间隔↑伤害↓；腿伤→移速↓；敌人不救同伴、不攻击倒地者。

5.2 AI 与行为 AI

用有限状态机驱动，敌我共用骨架、按阵营填参数：

idle → 发现目标 → chase → 进入射程 → attack
                        ↓ 目标太远/危险
                      flee → idle
down/dead → 退出状态机
  • 狼群：敌对所有阵营，可被引导去咬敌人（诱饵机制）。
  • 小队指令：左键选人、右键移动/攻击、Tab 全选、空格停下、T 自动反击。
  • 寻路：网格贪心 + 简单避障；大规模用 A*（按需）。

5.3 生存系统 Survival

  • 饥饿：饱食度随时间下降，归零开始掉血；F 消耗干粮进食。
  • 扎营/睡眠：V 消耗营地套装搭篝火+帐篷；Z 在火旁睡到天亮，大幅恢复。
  • 资源：猫币🪙 / 干粮🍖 / 绷带🩹 / 建材🧱，HUD 顶部展示。

5.4 经济与物品 Economy

  • 物品定义全部进 data/items.js（名称/类型/价格/效果），逻辑只读表。
  • 商店（E）买卖、招募；价格可随供需浮动（可选）。
  • 击杀掉落 → 战利品结算进背包。

5.5 地图与生成 Spawner

  • 枢纽镇为中心，离镇越远敌人越强、越密集（已在 HUD 提示）。
  • 网格空间分区加速碰撞/查询；静态地形层用离屏 canvas 缓存。
  • 昼夜：白天/黑夜切换影响视野与刷新。

六、游戏循环与状态机

固定步长（如 60Hz）驱动；渲染最后执行。这样同一帧序列可确定性复现，便于用无头测试复现你那个偶发左键移动失败。

八、开发里程碑（分阶段，每阶段带测试）

阶段 1 · 核心循环：抽出 World + Actor + Engine，跑通「选人→移动→攻击→击杀」，保留现有无头测试。
阶段 2 · 生存与部位伤害：Body 六部位、流血/自愈、饥饿/绷带/睡眠、HUD 显示。
阶段 3 · 经济与内容：物品表、商店、招募、Spawner 难度梯度、地图纵深。
阶段 4 · 建造与扩展：围墙/篝火、俘虏、狼群 AI、MOD 化数据表。
阶段 5 · 打磨：性能优化、存档、平衡、UI 润色。

九、测试策略

  • 沿用：你已有的 test-smoke.js（无头跑主循环验核心流程）与 debug-trace.js（逐帧追踪偶发 bug）。
  • 扩展：把逻辑层改为可导入的 ESM，写 Vitest 单测覆盖 Combat 伤害表、AI 状态迁移、Survival 数值。
  • 确定性：固定步长 + 种子，CI 跑回归，任何改动先验证「左键走路/战斗/睡眠」不破。

十、风险与权衡

风险等级应对
范围蔓延（先加太多系统）高严格按里程碑，每阶段只加一个系统并写用例
性能：单位/特效多导致掉帧中网格分区 + 离屏缓存 + 视口裁剪
逻辑与表现耦合，测试难写中从第一天就保持逻辑层无 DOM 依赖
数值平衡失控低全部数值进 data/balance.js，配置化调参
结论：仿 Kenshi 的关键在于「部位伤害 + 技能成长 + 开放沙盒」三系统互相咬合，而非画面。按 引擎/世界/角色/战斗/AI/生存/经济/UI/存档 九模块拆分，逻辑与表现彻底分离，再用你已有的无头测试守住核心循环——这套结构能让你无限加内容而不重写。建议从「阶段 1：抽 World + Actor + Engine」开始，每一步都跑一遍冒烟测试。
