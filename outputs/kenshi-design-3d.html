荒原浪人 · 3D 版设计方案

WASTELAND RONIN — 仿 Kenshi 的网页 3D 沙盒生存游戏 · 全量设计（Three.js / WebGL）

确认：Kenshi 确实是 3D 游戏——它用 OGRE 引擎，角色与场景为 3D 模型，相机是可旋转的斜俯视视角。所以做 3D 更贴近原作。

关键优势：前面我们把逻辑层（World / Actor / Combat / AI）设计成不依赖 DOM、不依赖渲染，因此切换到 3D 时这些模块几乎不动，只需把「表现层」从 Canvas2D 换成 Three.js 场景图。下面给出 3D 专属的调整方案。

一、技术路线（替换项）

层2D 方案3D 方案（本版）
渲染Canvas 2D 色块Three.js（WebGL）+ 场景图 / Mesh
坐标2D (x,y)x,y 二维逻辑不变，渲染映射 z=高度/地面
相机正交平移透视/正交斜俯视，可旋转，WASD+右键拖拽
地形单张底图平面 + 高度图 或 地块网格
HUD/弹窗DOMDOM 叠加（不变）
测试无头 Node逻辑层无头不变；渲染层单独测

二、3D 场景与相机

Kenshi 风格的「斜俯视」用透视相机 + 固定俯角（约 50–60°）实现，比纯 2D 更有空间感，又保留俯视可读性。逻辑层仍用 2D 平面坐标，渲染时把 (x,y) 当作地面坐标，(z) 由模型自身高度给出。

三、架构调整（新增/改写模块）

逻辑层（World / Actor / Skills / Combat / AI / Survival / Economy）保持不变。需新增/改写的是「表现层」与「资源」相关部分：

Render3D

渲染层（改写）

  • Three.js Scene / Renderer / Camera
  • 实体→Mesh 映射（EntityView），状态变化同步
  • InstancedMesh 批量渲染大量单位
  • 地面/地形、光照、阴影
Camera

相机与控制

  • 斜俯视透视，滚轮缩放
  • WASD 平移、右键拖拽旋转、G 跟随
  • 屏幕↔世界坐标拾取（射线检测）
Assets

3D 资源

  • 先用基础几何体占位（box/capsule）
  • 后续换 glTF 角色/武器/建筑
  • 用 3D 生成工具产出占位/成品模型
Pick

鼠标拾取

  • Raycaster 命中实体/地面
  • 左键选人、右键移动/攻击映射回逻辑
  • 框选用屏幕矩形→世界投影

四、坐标与渲染映射

// 逻辑层（保持不变，仍是 2D 平面）
Unit = { x, y, ... }   // 地面坐标

// 渲染层映射
mesh.position.set(u.x, 0, u.y);          // 地面平面: x→x, y→z
mesh.scale  = bodyScale(u);              // 状态影响外形（残肢→缩部件）
mesh.rotation 由朝向给出

// 相机
camera.position = target + offset(俯角, 距离);
camera.lookAt(target);

五、性能考量（3D 专属）

  • 批量渲染：几十上百单位用 InstancedMesh，避免逐个 draw call。
  • 视锥裁剪：Three.js 自带，只绘制可见实体。
  • LOD / 远处简化：远处单位用低模或 billboard。
  • 静态层缓存：地形/建筑不每帧重建。
  • 逻辑仍 60Hz，渲染与逻辑解耦，掉帧不影响规则确定性。

六、内容/资源路线

资源先用后续
角色胶囊/盒体占位glTF 人形模型 + 部位拆分（对应六部位血量）
武器/护甲附加几何体glTF 道具，挂到角色骨骼

实际模型产出可走 3D 生成能力：文本/图片→3D 模型，先用占位，再替换为成品 glTF。

七、开发里程碑（调整为 3D）

阶段 1 · 逻辑核心：抽 World + Actor + Engine（同 2D 方案，无渲染），无头测试先跑通。
阶段 2 · 3D 渲染骨架：Three.js 场景 + 斜俯视相机 + 实体→Mesh 映射，用盒体占位把现有玩法在 3D 里跑起来。
阶段 3 · 交互与拾取：Raycaster 鼠标选人/移动/攻击、框选、相机控制。
阶段 4 · 生存与部位系统：六部位血量可视化（模型部位变色/缺失）、流血/睡眠/扎营。
阶段 5 · 内容替换：占位换 glTF 模型、物资/商店、Spawner 难度梯度、地图纵深。
阶段 6 · 打磨：光照/阴影、性能、存档、平衡。

八、风险与权衡（相较 2D）

风险等级应对
3D 学习/调试成本更高高先用占位几何跑通逻辑，模型后置；逻辑层可独立测试
性能（draw call/阴影）中InstancedMesh + 视锥裁剪 + 静态缓存
模型资源缺失中占位先行，按需用 3D 生成工具产出
相机/拾取复杂度中Raycaster 统一处理点选/框选，逻辑不变
结论：Kenshi 是 3D，做 3D 更还原。技术路线用 Three.js（WebGL），逻辑层（World/Actor/Combat/AI）沿用之前的设计无需重写，只需新增「渲染层 + 相机 + 资源/拾取」。先以盒体占位把 2D 玩法在 3D 里跑通，再逐步替换真实模型。HUD、小地图、弹窗仍用 DOM 叠加，不进 3D 场景。
